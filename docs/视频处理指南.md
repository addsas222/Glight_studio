# 视频处理操作指南

本文档说明如何用凌日光影棚处理**视频**：导入、选择处理模式、预览与逐帧检查、
导出，以及性能与排障。

适用版本：1.0 ｜ 相关文档：[用户手册](./用户手册.md)、[API接口文档](./API接口文档.md)

---

## 一、支持范围

| 项 | 说明 |
|---|---|
| 输入格式 | **MP4 / AVI / MOV**（另支持 MKV / M4V / WEBM） |
| 建议分辨率 | **≤ 1080p**（长边 ≤1920） |
| 建议时长 | **≤ 5 分钟** |
| 硬性上限 | 长边 ≤4096、时长 ≤30 分钟（超出直接拒绝并说明原因） |
| 输出 | **同格式视频**，与输入**同分辨率、同帧率、同帧数** |
| 音轨 | **原样保留**（音频直通复制，只重编码视频） |

> 超过建议范围不会报错，但界面会提示「建议启用云端 AI」以获得更好的深度质量；
> 同时处理时间会显著增加。

---

## 二、快速上手

1. 点顶栏「**打开视频**」，选择 MP4/AVI/MOV 文件；
2. 软件读取元数据（分辨率、帧率、时长、帧数、是否有音轨）并显示在状态栏；
3. 选择**处理模式**（关键帧传播 / 逐帧分析，见第三节）；
4. 调光照（与图片完全相同：预设、光源、轨迹球、环境光，见用户手册第 6–9 节）；
5. 点「**开始处理**」，进度条显示阶段与百分比；
6. 完成后点「**导出视频**」保存到你指定的路径。

处理在后台线程执行，**界面不会卡死**；可随时点「取消」，半成品文件会被自动清理。

## 三、两种处理模式

### 3.1 关键帧分析传播（默认，推荐）

- **做法**：先用场景变化检测选取若干关键帧（默认 8 帧，始终包含首帧与末帧），
  只对这些关键帧做 AI 深度分析；其余帧的深度在相邻关键帧之间**线性插值**，
  并在时间轴上做 EMA 平滑抑制闪烁。
- **光照**：全片使用**同一套光照参数**，因此风格稳定统一。
- **速度**：快。AI 分析次数 = 关键帧数量（与总帧数无关），
  主要耗时在逐帧渲染。
- **适合**：加查动画、立绘式角色动画、镜头与人物位置变化不剧烈的片段。

关键帧数量可调：帧数越多越贴合画面变化，但 AI 分析次数相应增加。

### 3.2 逐帧分析（高质量）

- **做法**：**每一帧**单独做 AI 深度分析，深度随画面实时变化。
- **光照**：随画面动态变化，人物移动时受光关系随之改变。
- **速度**：慢，**与帧数成正比**。
- **适合**：镜头运动明显、人物进出画面、遮挡关系复杂、或需要逐帧精确受光的片段。

> 两种模式都会把 AI 结果写入本地缓存：同一段视频重复处理时，
> 关键帧/帧的深度**不会重复计算**。
>
> **磁盘占用提醒**：逐帧模式会为**每一帧**写入一份深度缓存（全分辨率 PNG），
> 1080p 约每帧百 KB 量级——10 秒片段约几十 MB，5 分钟长片可达 **GB 级**，
> 且缓存只增不减。处理长视频建议用关键帧传播模式，或处理完在
> 「设置 → 清理缓存」中释放空间。

## 四、预览与逐帧检查

- **播放预览**：处理前后都可播放视频预览，确认光照氛围。
- **逐帧检查**：用帧步进（上一帧/下一帧）或输入帧号跳转，
  逐帧查看光照效果；画布显示当前帧的像素坐标。
- **在某一帧上拾取主光**：进入「拾取主光」模式后，在当前帧画面中点击像素，
  主光源即锚定该点**法线的逆方向**——与图片的拾取行为完全一致。
  这对「某个镜头的光要打在这个角色的脸上」这类需求特别有用。
- **深度图查看**：可切换显示当前帧的深度图，确认 AI 对前后关系的判断是否正确。

## 五、性能参考与预期

实测环境：Intel i7-9750H（6 核 12 线程），CPU 推理，**关键帧模式**。

| 视频 | 帧数 | 实测耗时 | 规格上限 |
|---|---|---|---|
| 320×240 · 15fps · 2s | 30 | ≈ 3.4s | — |
| **1920×1080 · 30fps · 10s** | **300** | **≈ 96.7s** | **≤ 5 分钟** |

要点：

- **逐帧渲染内存平稳**：1080p 全片处理过程内存增长约 122MB。深度按帧流式生成，
  不会把整片深度读进内存（若一次性物化，1080p 10 秒就需约 2.5GB、5 分钟约 75GB）。
- **输出分辨率不影响速度**：光照在代理分辨率上计算后上采样，
  因此 1080p 与 4K 的渲染耗时接近，但输出仍是原分辨率。
- **高质量物理阴影**：把「性能模式」切到高质量时，逐帧渲染耗时增加
  （每帧都要做阴影投射）。视频建议先用快速预览调参，确认后再用高质量出片。

### 预计耗时估算

```
关键帧模式总耗时 ≈ 关键帧数 × 单帧AI分析 + 总帧数 × 单帧渲染
逐帧模式总耗时   ≈ 总帧数 × (单帧AI分析 + 单帧渲染)
```

单帧渲染耗时与分辨率、光源数量、性能模式相关（见用户手册「性能参考」一节）。

## 六、常见问题

**Q：为什么输出视频没有声音了？**
正常情况下音轨会原样保留。若源文件音轨编码特殊（少见），
可在导出的同时勾选保留原音轨；仍失败时先用 ffmpeg 转封装一次源文件再试。

**Q：画面出现闪烁（明暗抖动）？**
关键帧模式已内置时间轴平滑。若仍明显，可增加关键帧数量，
或改用逐帧模式（代价是耗时增加）。

**Q：处理到一半可以取消吗？**
可以。点「取消」后软件会中止并删除半成品文件，不会留下损坏的视频。

**Q：视频很长（超过 5 分钟）怎么办？**
先剪成片段分别处理再拼接，或直接处理——软件允许到 30 分钟，
但耗时与内存占用都会显著上升。

**Q：一定要装 ffmpeg 吗？**
不需要单独安装。软件依赖 `imageio-ffmpeg` 提供的**随包静态 ffmpeg**，
`pip install -r requirements.txt` 即已包含。若要指定自己的 ffmpeg，
可设置环境变量 `HLS_FFMPEG` 指向其可执行文件路径。

**Q：支持哪些输出格式？**
与输入同格式：`.mp4` / `.m4v` / `.mov` / `.mkv` 用 H.264（libx264），
`.avi` 用 MPEG-4 Part 2（mpeg4）。输出另存为新文件，原视频不受影响。

## 七、命令行与 API

批处理或二次开发时可用 API（见 [API接口文档](./API接口文档.md) 的视频章节）：

- 上传：`POST /api/video`
- 取帧 / 关键帧 / 帧上拾取：`POST /api/video/frame`、`/api/video/keyframes`、`/api/video/pick`
- 开始处理（后台任务）：`POST /api/video/process` → 轮询 `GET /api/video/job/{job_id}`
- 取消：`POST /api/video/job/{job_id}/cancel`
- 下载成品：`GET /api/video/result/{video_id}`
- 清理：`POST /api/video/delete`

单张图片的批处理仍可用命令行：

```bash
python hls_cli.py --preset 逆光黄昏 --lighting hq in.png out.png
```
