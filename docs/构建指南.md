# 构建指南

面向从源码构建出安装包 / 部署本地服务的开发者。
只使用软件的用户请看 [用户手册.md](./用户手册.md)。

## 零、环境准备

- Python **3.10 ~ 3.14**（64 位；本仓库已在 **3.14.7 + PyInstaller 6.22.2** 上
  实测打包出可运行的 Windows exe，并在 **3.12.13（uv 环境）** 下跑通全部测试）
- **Node.js 18+** —— 仅在**构建前端界面**时需要；运行期不需要 Node
- 依赖清单（两种安装方式等价，改依赖时**两处需同步**）：
  - `pyproject.toml` + `uv.lock` —— **uv 方式**（推荐）：
    `uv sync` 按锁文件精确复现环境
  - `requirements.txt` / `requirements-dev.txt` —— **pip 方式**
  - `server/requirements.txt` —— 本地自建深度服务（独立部署，另装）

```bash
# 方式一：uv（推荐）
uv sync                            # 含开发工具（pytest / pyinstaller / playwright）
uv sync --no-dev                   # 只装运行期依赖
uv run python -m pytest tests/ -q  # 引擎与视频单元测试
uv run python -m webui.desktop     # 运行软件

# 方式二：pip
pip install -r requirements-dev.txt
python -m pytest tests/ -q
```

> 国内网络较慢时可换源加速：
> `UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple uv sync`

### 界面端到端测试（拟人点击）

`tests/ui_playwright.py` 用 Playwright 以**拟真输入**驱动界面：鼠标分步移动到元素
再按下/抬起、键盘逐字符输入、`mouse.down/move/up` 分步拖拽（轨迹球、推子、画布平移）、
`mouse.wheel` 缩放、真实文件选择。覆盖 13 个界面的切换、主题切换、预设、轨迹球与
点光切换、滑杆拖拽、滚轮缩放、图片导入与渲染、**视频导入自动切屏并载入**、
视频逐帧/播放、CUE 保存、遥测滑杆、插件与主题屏、Tab 焦点，共 34 项断言。

```bash
# 需先安装浏览器（国内可用镜像加速）
pip install playwright
PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright \
  python -m playwright install chromium

python -m webui.api --port 8756 &        # 先启动服务
python -m tests.ui_playwright            # 全部用例
python -m tests.ui_playwright 主题        # 只跑名字含「主题」的用例
```

截图输出到 `build/ui-shots/`。可用 `HLS_BASE` 指定服务地址、
`PLAYWRIGHT_BROWSERS_PATH` 指定浏览器路径。

**防挂死**：整套跑在子进程里，父进程做墙钟上限看门狗，超时会杀掉子进程
（连 Chromium 一起）并打印**最后进入的用例名**——`page.evaluate` 没有默认超时，
页内 `await` 若永不 settle 会永久卡住驱动调用，只能在进程外打断。

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `HLS_RUN_TIMEOUT` | 1500 | 整轮硬上限（秒），超出即终止并报出卡住的用例 |
| `HLS_CASE_WARN` | 120 | 单用例耗时超过该值就标记「偏慢」（仅提示，不判失败） |
| `HLS_NO_WATCHDOG` | — | 设为 1 则不启子进程，直接在当前进程跑（调试用） |

> 不要给单用例加**线程**看门狗：Playwright 同步 API 走 greenlet dispatcher，
> dispatcher 绑定创建它的线程，从别的线程调 `page`/`ctx` 会抛
> `greenlet.error: Cannot switch to a different thread`（实测），用例会全灭。

**可选的重型用例**：默认会跳过「真实 66MB 模型导入」这一条（要几十秒，
跑两次会让整套超时）。需要时显式打开：

```bash
HLS_TEST_MODEL_IMPORT=1 python -m tests.ui_playwright 离线
```

> 「离线导入」控件的接线本身由另一条**确定性**用例覆盖（用伪造文件断言
> 错误提示），因此默认套件在任何机器上都能稳定跑完。

> 三个打包脚本都会自动执行「构建前端 → 打包」，并在缺少 Node 时明确报错，
> 不会静默产出没有界面的空壳程序。

## 一、Windows → `HorizonLightStudio.exe`

```bat
cd horizon-light-studio
packaging\build_windows.bat
```

脚本流程：虚拟环境 → 安装依赖 → **构建前端**（`webui/frontend` → `dist`）→
生成图标 → PyInstaller 打包 → 输出产物。

**产物**

| 文件 | 说明 |
|---|---|
| `dist\HorizonLightStudio.exe` | 独立桌面软件（**单文件绿色版**，双击即用） |
| `dist\hls_cli.exe` | 命令行渲染器（图片批处理，可选） |

打包配置为 `packaging/horizon_light_studio.spec`：入口是 `webui/desktop.py`，
并把 `webui/frontend/dist`（界面）、`docs/`、`server/` 与 **ffmpeg 二进制**
一并纳入分发包。

**可选：生成安装程序（带开始菜单快捷方式）**

```bat
packaging\make_installer_windows.bat
```

需先安装 [Inno Setup 6](https://jrsoftware.org/isdl.php)，
产出 `dist\HorizonLightStudio-1.0.0-Setup.exe`
（图标、中文名称、版本信息、桌面快捷方式、卸载程序，并附带 docs 与 server）。

版本元数据在 `packaging/version_info.txt`，安装脚本在
`packaging/make_installer_windows.iss`。

## 二、macOS → `.app` + `.dmg`

> **验证状态**：本脚本**尚未在 macOS 上执行过**（开发环境为 Windows）。
> 首次在 mac 上运行时如遇路径/工具差异，请以脚本内注释为准调整。

在 macOS 上执行（需 Xcode 命令行工具；`sips`/`iconutil`/`hdiutil` 系统自带）：

```bash
bash packaging/build_macos.sh
```

**产物**

- `dist/凌日光影棚.app`
- `dist/凌日光影棚-1.0.0.dmg`

脚本会：生成图标并转成 `.icns` → PyInstaller 打包为 `.app` →
用 `create-dmg`（若已安装）或系统 `hdiutil` 封装 `.dmg`。

**签名与公证**（正式分发必需，需 Apple 开发者账号）：

```bash
codesign --deep --force --options runtime \
  --sign "Developer ID Application: <你的名称> (TEAMID)" "dist/凌日光影棚.app"

xcrun notarytool submit "dist/凌日光影棚-1.0.0.dmg" \
  --apple-id <邮箱> --team-id <TEAMID> --wait
xcrun stapler staple "dist/凌日光影棚-1.0.0.dmg"
```

未签名分发时，用户首次打开会看到「无法验证开发者」，
可在「系统设置 → 隐私与安全性」点「仍要打开」，或：

```bash
xattr -dr com.apple.quarantine "/Applications/凌日光影棚.app"
```

## 三、Linux → `.AppImage`

> **验证状态**：本脚本**尚未在 Linux 上执行过**（开发环境为 Windows）。
> 首次运行时会联网下载 `appimagetool`，请确保网络可用。

```bash
bash packaging/build_linux.sh
```

**产物**：`dist/凌日光影棚-1.0.0-x86_64.AppImage`

脚本会：PyInstaller 打包为 onedir → 组装 `AppDir`
（`usr/bin` + `.desktop` + 图标 + `AppRun`）→ 下载 `appimagetool`
（首次需联网，缓存于 `build/`）→ 生成 AppImage。

运行：

```bash
chmod +x "dist/凌日光影棚-1.0.0-x86_64.AppImage"
"./dist/凌日光影棚-1.0.0-x86_64.AppImage"
```

若无 FUSE：追加 `--appimage-extract-and-run`。

相关文件：`packaging/linux/AppRun`、`packaging/linux/app.desktop`。

## 四、打包配置说明

`packaging/horizon_light_studio.spec` 是**跨平台** PyInstaller 配置，
按运行平台自动分支：

| 平台 | 布局 |
|---|---|
| Windows | `onefile` → 单个 `HorizonLightStudio.exe` |
| macOS | `onedir` + `BUNDLE` → `凌日光影棚.app`（含 Info.plist） |
| Linux | `onedir` → 供 AppImage 组装的 `dist/HorizonLightStudio/` |

同时会额外打包命令行渲染器 `hls_cli`。

**图标**由 `packaging/make_icon.py` 用纯 PIL 生成（`packaging/icons/`），
无需外部素材，可随时重新生成。

## 五、本地深度服务部署

```bash
server/setup_deployment.sh      # Windows: setup_deployment.bat
server/run_server.sh            # Windows: run_server.bat
```

部署脚本：创建**服务专用虚拟环境 `.venv-server`**（与开发用的 `.venv` 分开，
避免与 uv 管理的环境互相覆盖）→ 安装 `server/requirements.txt` →
下载 Depth Anything V2 Small（约 94MB，走 `hf-mirror.com` 镜像）。
MiDaS-small 与 MoGe-2 法线模型可选，也能放进同一模型目录被自动识别。

**注意**：服务在**模型缺失时返回 HTTP 503**（不伪造深度），
桌面软件据此降级。若只想要「服务能起来」而不下载模型，
接口会明确报错，属预期行为——请用 `--preview-only` 走灰度模拟。

接口细节见 [API接口文档.md](./API接口文档.md)。

## 六、开发环境

```bash
pip install -r requirements-dev.txt

python -m pytest tests/ -q          # 单元测试（核心引擎）
python -m webui.desktop             # 启动桌面软件（本地服务 + 界面）

```

## 七、GIMP 插件（可选，超出核心交付范围）

> 桌面软件本身已完整独立，不需要任何图像编辑宿主。本节仅供同时使用 GIMP 的用户。

1. 复制 `gimp_plugin/hls_light.py` 到 GIMP 插件目录：
   - Windows：`%APPDATA%\GIMP\2.10\plug-ins\`
   - Linux/macOS：`~/.config/GIMP/2.10/plug-ins/`（`chmod +x`）
2. 让插件找到渲染核心：把 `hls_light.py` 与 `hls_cli.exe` 放在同一目录，
   或设置环境变量 `HLS_HOME` 指向仓库根目录（需系统 Python 3）；
3. 重启 GIMP → 滤镜 → 凌日光影棚 → 智能光照增强…

实现上插件通过**子进程**调用 `hls_cli`，因此与 Qt 无关，
在 GIMP 2.10 的 Python 2.7 环境中也能运行。
